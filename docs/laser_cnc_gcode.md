# Laser and CNC G-code format (IVI 3licer 1.6.2)

Reverse-engineered on 2026-11-01 from three test files Jeffery generated with IVI 3licer 1.6.2
(laser line mode, laser point mode, CNC carve). Only short excerpts are reproduced here.
**None of these files has been run on the printer by us — everything below is unverified on hardware.**

## Header (all job types)

Every file starts with a fixed comment header, in this order:

```
;Header Start
;header_type: laser            ; laser | cnc  (3dp for FDM)
;renderMethod: line            ; line (vector) | point (dot/raster)
;file_total_lines: 64915       ; all lines in the file, header included
;file_valid_lines: 64892       ; non-comment lines (IVI also counts one whitespace-only line, so +1)
;estimated_time(s): 1542.7857574567083
;max_x(mm): 49.75
;max_y(mm): 50.63
;max_z(mm): 0                  ; always 0, even for CNC that cuts to Z-3.20 and lifts to Z10
;min_x(mm): -49.75
;min_y(mm): -50.88
;min_z(mm): 0
;work_speed(mm/minute): 500
;jog_speed(mm/minute): 1500
;power(%): 100
;Generated by IVI 3licer
;Header End
```

The X/Y bounds equal the extremes of all G0/G1 moves (verified on all three samples). The bounds are
roughly symmetric around 0: **jobs are centre-origin** (X0 Y0 = centre of the work area), and every job
ends with `G0 X0.00 Y0.00`. After the header: a blank line, `;G-code for laser engraving` (laser only),
`;Generated by IVI 3licer`, a date comment, a line containing one space, then `G90`, `G21`.
Coordinates are always written with 2 decimals, and X and Y are both written on every move.
How the firmware uses the header (bounds check, progress, time display) is unknown.

## Laser — line (vector) mode — primary reference

```
G90
G21
; G-code START <<<
M106 P0            ; IVI 3licer emits this. On a laser head the firmware sends nothing
G0 F1500           ; jog speed
G1 F500            ; work speed
G0 X6.00 Y-50.88   ; travel, laser off
M3 S100            ; laser ON, S = power in percent (first time only)
G1 X6.25 Y-50.88   ; burn
M5                 ; laser OFF after each burn segment
G0 X0.50 Y-50.63
M3                 ; bare M3 re-uses the last S
G1 X0.25 Y-50.63
M5
...
G0 X0.00 Y0.00
M107 P0            ; IVI 3licer emits this. On a laser head P1 restarts within about 1 s
; G-code END <<<
```

Command forms in the sample: `G0 X Y`, `G1 X Y`, `G0 F`, `G1 F`, `M3 S`, bare `M3`, `M5`, `M106 P0`, `M107 P0`.
No arcs, no Z, no `G4`. 32,443 moves / 32,441 M-codes for a 100 × 101 mm image.

`M106 P0` in these files is the slicer's fan line. The firmware has no air-assist output, and on a laser head that command sends no CAN frame. The heatsink fan is P1. The auto-fan rule is on from boot and forces P1 on every second. Detail: [stm32.md](stm32.md#fans) and [stm32.md](stm32.md#laser).

Caveats: `S` is **percent (0–100)** and indexes a 101-byte table in the firmware (S1 sends `B1` 50, S100 sends 255). **S above 100 reads past that table.** What the head does with the byte is unmeasured. Marlin normally shares one modal feed rate between G0 and G1, so whether
`G0 F1500` / `G1 F500` really give separate jog/work speeds on this firmware is unverified.

## Laser — point (dot) mode — slicer bug

```
M106 P0
G1 F40
G1 X-49.75 Y-9.38
G4 P896745231 L100     ; dwell + laser pulse at 100 %
G1 X-49.25 Y-9.13
G4 P896745231 L        ; bare L re-uses the last power
...
G0 X0.00 Y0.00
M107 P0
```

The IVI-specific `G4 P<ms> L<power>` fires the laser for the dwell time. **The dwell `P896745231`
(≈ 10.4 days per dot) is a bug in IVI 3licer 1.6.2**, which is also why the header says
`estimated_time(s): 66734374055` (≈ 2,100 years). Don't run point-mode files from this slicer version,
and don't copy the value. A sane dot dwell is probably a few ms to tens of ms; the units of `P`
(ms as in Marlin, or µs) are unverified. The Fusion posts never emit point mode.

## CNC

```
G90
G0 Z10.00 F400       ; safe height
G0 X-30.00 Y-22.35 F400
G0 Z5.00 F400        ; retract height
M3 P100              ; spindle ON, P = percent
G0 Z5.00 F3000
G0 X-30.00 Y-22.35
G1 Z-0.40 F300       ; plunge
G1 X-28.58 Y-21.97   ; cut
...
G0 Z5.00
G0 Z10.00
G0 X0.00 Y0.00
M5                   ; spindle off
```

Command forms: `G0 X Y`, `G0 Z`, `G0 Z F`, `G0 X Y F`, `G1 X Y`, `G1 Z F`, `M3 P`, `M5`, `G90`.
Depth in passes of 0.40 mm down to Z-3.20 (8 passes). Z0 = stock top, cuts are negative.
Note `G21` is absent from the CNC sample (mm assumed by default); the Fusion post adds it.

Caveat: the firmware's M3 handler **ignores P** (see findings below), so `M3 P100` behaves like a bare `M3`
(re-uses the last power). `M3 S<percent>` is what the firmware actually reads; the Fusion CNC post emits S by default.

## Start sequences seen on the printer (2026-11-01, USB, from IVI 3licer)

| Step | Laser | CNC |
|---|---|---|
| On connect (IVI 3licer server code) | `M2005`, `M2051`, `M2007`, `M105`, `M2155 S4` | same |
| Home button (app code `executeGcodeAutoHome`) | `G53`, `G28`, `G54`* | `G53`, `G28`, `G54` → `Select workspace 0` |
| Start | `M1001 L` (fw ≥ 2.4.0 only), `M2411 S2` → `PC start work` / `trigger work: ok` | same |
| File | `G90`, `G21`, `M106 P0`, `G1 F500`, `G1 X-49.75 Y-9.38`, `G4 P45 L100` … | `G90`, `G0 Z10 F400`, `G0 X-30 Y-22.35 F400` … |

*Observed laser log had `G53`, `G28`, `G90` — no `G54`; the app sends `G54` only for laser/CNC head types it recognises.
If "focus height" is enabled the app also sends `G53; G0 Z<focus+thickness> F1500; G54;` before the job.

What happened: the laser job stalled at its **first** sideways move twice (`warning:DriveX locked rotor` ~2 s later, then
`PC trigger pause`); the CNC job (which drops to Z10 first) moved normally until the user e-stopped (`Printer halted. kill() called!`).

## Firmware findings (2026-11-01)

From the motion firmware (`firmware.supx` → `supx_raw.bin`, base 0x08010000, Ghidra decompile) and IVI 3licer 1.6.2
`server/index.js` / app bundle. **[C]** = confirmed in code, **[I]** = inferred.

### Host commands
| Command | Meaning | Evidence |
|---|---|---|
| `M2007` | Status block: position, origin offsets, `Working Status: IDLE / WORKING_PC / WORKING_SCREEN / ERROR` [C] | dispatcher 0x7D7 → FUN_08025D60 → FUN_08025C30 (strings 0x08035C66…0x08035C96) |
| `M2155 S<n>` | Auto-report every *n* s (0 = off, max 60): temps, driver encoder `Count A/B/C`, the M2007 block [C]. This is the unsolicited status every ~4 s | FUN_080212DC stores n and deadline; timer FUN_0802601C calls FUN_08025D24, FUN_0802922C (Count), FUN_08025D60 |
| `M2410` | Pause. Not in the normal dispatcher (FUN_08021390 is empty) — caught by the byte-level emergency parser (FUN_0801A510/FUN_08019928) → FUN_0801A748 prints `PC trigger pause` / `SC trigger pause` (port that sent it) [C] | strings 0x080347AB/0x080347BA |
| `M2411 S1` | Resume (only from status 5, same port that owns the job) [C] | FUN_080267C0 |
| `M2411 S2` | Start PC job (only from status 1) → `PC start work`, `trigger work: ok`; else `Can't start work in current status: N` + `start work failed, err= 200` [C] | FUN_080268FC, string 0x0803610B |
| `M2411 S3` | **Stop** (from status 2, 5 or 8; owner port must match). From 5 → status 10 → `Finish stop` → 1. Turns the laser off [C]. IVI 3licer's Stop button sends it, and sends it on connect if `Working Status: WORKING_PC` [C] | FUN_08026708 (mask 0x124), FUN_08026858, server `gcode:stop` |
| `M2411 S4` | Finish (status → 9) [C] | FUN_08021394 case 4 |
| `M2411` other S | ignored (switch default) [C] | |
| `M1001 L` / `M1001 U` | Sent by IVI 3licer only when firmware ≥ 2.4.0 (L on start/resume, U on pause) [C]; not in V1.3.2's dispatcher [I: Snapmaker 2.0 lock/unlock heritage] | server code |
| `M20` | not implemented → just `ok`, no file list [C: no case 20 in dispatcher] | FUN_080230F8 |

### Job status numbers (`current status: N`)
0 INIT, 1 IDLE, 2 WORK, 3 PAUSE_TRIG, 4 PAUSE_STOPPED, **5 PAUSE_FINISH = paused**, 6 RESUME_TRIG, 7 RESUME_MOVING,
8 RESUME_WAITING [C: IVI 3licer table `SYSTAT_*`; firmware transitions 2/8→3 (pause), 4→5 (`Finish pause`), 5→6 (resume)],
9 stopping, 10 stopping-from-pause [C: FUN_08026708].
**`Can't start work in current status: 5`** = the previous job is still paused. Clear it with `M2411 S3` from the same port
(or resume with `M2411 S1`) [C]; the bridge does this automatically once. If the touch screen owns the job, the PC port
gets `current working port is not PC!` — stop it on the screen [C].

### Kill
`Printer halted. kill() called!` is Marlin's `kill()` (e-stop, MAXTEMP etc.). Marlin's kill loop stops processing
commands; recovery is a power-cycle/reset [I: standard Marlin; `M999` only clears the softer `Stopped` state].

### "warning:DriveX locked rotor"
- The **closed-loop driver** detects it and reports bit 1 of its status register 0x14 over UART; the mainboard just prints
  `warning:` + `DriveX/Y/Z/E0 ` + `locked rotor` and disables further fault reports (FUN_0802DE40 → FUN_0802DD38) [C].
  No threshold lives in the mainboard firmware — it is inside the driver [C for absence, I for location].
- The mainboard does **not** pause by itself; IVI 3licer matches `^warning:Drive(.*) locked rotor$` with `shouldPause`
  and sends `M2410` → `PC trigger pause` [C]. That is the pause seen today.
- `Count A/B/C` in the auto report = encoder counts of the three tower drivers [I: printed by FUN_0802DAE4 from the driver table].
- **Why the first laser move stalls [I, strong]:** this is a delta (L 357.5, R 160.31, H 233.2). After `G28` the carriages sit
  at the top endstops. Moving to X-49.75 Y-9.38 at that height needs the X (A) carriage to rise **+19.4 mm above its
  homed position** (Y −24.2, Z −8.8 mm) — physically impossible, so the X motor stalls. The laser file contains no Z move,
  and without `G54`/focus-height Z the head stays at Z≈237. The CNC file drops to `G0 Z10` (workspace) first, so it moved.
  Fix: lower the head before the first XY move (IVI 3licer's focus-height option, or the bridge's `laser_focus_z`).
  Even a 5 mm sideways move at the top needs +2.1 mm carriage travel.

### Laser / CNC power
- `M3` [C, FUN_08021FB0]: **P is never read**, so `M3 P100` is a bare `M3`.
  Laser (class 1): `M3 S<n>` waits for queued moves, indexes the 101-byte power table, and sends CAN `B1` with that byte. S is percent 0–100. **S above 100 is clamped only to 255 and reads past the table.** Bare `M3` re-sends the last S. `M4` is the same handler. Ignored for 3 s after a pause starts. Table and the arm-at-boot `B2 01`: [stm32.md](stm32.md#laser).
  CNC (class 2): `M3 S<n>` is clamped to 100, enables the head (CAN `B8 1`) and **ramps in 10 % steps every 300 ms**; bare `M3` re-uses the stored value.
- `M5` [C, FUN_08022030]: laser `B1 00` (last S kept, so a later bare `M3` restores it); CNC power 0 + `B8 2` (head off).
- `G4 P<ms> L<n>` [C, FUN_080246D0]: Marlin dwell (P ms, S s); `L` is honoured only with the laser head: `L<n>` fires at
  `table[n]` for the dwell, then `B1 00`. Bare `L` re-uses the last S. So the bogus `P896745231` really would dwell ~10 days per dot.
  The `G4 P45 L100` seen today is a sane 45 ms dot.
- `M106` / `M107` [V, FUN_080256A4]: head fans are on/off over CAN, not PWM. There is no air assist. **`M106` with no `P` turns both fans on and ignores `S`**, so `M106 S0` turns them **on**. `M107` turns both off and ignores `P`. `P0` is sent only for an FDM head (CAN `B3`); `P1` is sent for every head class (CAN `B4`). On a laser or CNC head, `M106 P0` sends nothing. The auto heatsink-fan rule is **on from boot**. With a laser head the 1 s tick forces P1 on, so `M107` holds for at most about 1 s unless `M2006 S0` was sent first. Detail: [stm32.md](stm32.md#fans).
- IVI 3licer's UI parser shows `M3 P` as % and `M3 S` as S/255 % (Snapmaker convention) [C] — display only.

## Open questions (need a hardware test, low power / scrap / safety glasses)
1. Laser `M3 S`: the firmware sends a table byte (S1 → 50, S100 → 255), and the head's reading of that byte is unmeasured. Lowest S that marks is unmeasured. **Do not send S above 100.**
2. Do `G0 F` and `G1 F` keep separate feeds?
3. Does the firmware reject files whose header bounds or line counts don't match?
4. Point mode dwell units; does `L` without `G4` do anything?
5. CNC: confirm `M3 S<percent>` spins (decoded: S read, P ignored, 10 %/300 ms ramp — so ~3 s to full before plunging).
6. Laser-head fan: installed at power-on, `M107` should drop P1 and the 1 s tick should bring it back; `M2006 S0` then `M107` should leave it off.
7. Door-open prints `warning:Door opened` and leaves `B1` unchanged. Whether the touchscreen pauses is unmeasured. The bridge does not watch the warning.
8. After a touchscreen stop (`M104 S0` → `B2 00`), whether a following laser job still fires.

Fusion post processors that follow these formats: [../fusion/README.md](../fusion/README.md). Proposed post changes (clamp S to 0–100, `M106 P1`, keep the auto-fan rule, drop the air-assist property) are pending a hardware test and are not in this tree.
