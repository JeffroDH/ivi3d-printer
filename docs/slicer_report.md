# IVI 3licer 1.6.2: printer communication analysis

The DMG was extracted with 7-Zip 24.08 (`/tmp/7zz`) into `/workspace/ivi/dmg/`.
Bundle: `IVI 3licer.app/Contents/Resources/app/` (unpacked Electron app, no asar).

## 1. Stack
- **Type:** Electron. It is a rebrand of **Snapmaker Luban / Snapmakerjs** (package.json `ivi-3licer` 1.6.2, AGPL-3.0; app-update.yml points to github whimsycwd/Snapmakerjs).
- **Backend:** `server/index.js` (webpack-minified Node; express, socket.io, serialport 8, dgram, superagent).
- **UI:** `app/app.93d080c0af402b41e438.bundle.js`, which contains the HTTP printer client (class `Server`).
- **Slicer engine:** CuraEngine 3.6, `resources/CuraEngine/3.6/macOS/CuraEngine`. Printer definition: `resources/CuraEngine/Config/ivi3d.def.json` (name "IVI 3D Printer"; 210x210x220; heated bed; origin at center (`machine_center_is_zero=true`); Marlin flavor; 0.3 mm nozzle).

## 2. Wi-Fi protocol (Snapmaker 2.0 HTTP API, unchanged)
### Discovery (server/index.js, module `lib:deviceManager`)
- Opens a UDP4 socket on an ephemeral port with broadcast enabled. It sends the ASCII `discover` to each interface's **directed broadcast address on UDP port 20050**.
- Replies are parsed as `name@ip|Key:Val|Key:Val`. Keys are lowercased, e.g. `IVI3D@192.168.50.85|Model:IVI 3D Printer|status:IDLE` becomes `{name:"IVI3D",address:"192.168.50.85",model:"IVI 3D Printer",status:"IDLE"}`.
- Results are emitted as `http:discover`. Discovery runs for a 3 s window.
### Control (app bundle, `t.Server`)
- `this.port = a || 8080`, so the base URL is **`http://<ip>:8080`**. Requests use form-urlencoded bodies (superagent `.send("k=v")`) or multipart forms.
- **Default token** (set in `_stateInit`): `e0cf19a3-e0a4-4740-825f-bdffb49e58b8`.

| Action | Request |
|---|---|
| connect | POST `/api/v1/connect`, body `token=<tok>` (empty on first connect). If the response is 403, it retries with no token. The response JSON includes `token`, `series`, `headType`. The user may need to confirm on the printer screen; the first successful status call confirms. |
| disconnect | POST `/api/v1/disconnect` `token=` |
| status (1 s poll) | GET `/api/v1/status?token=`. JSON: `status` (IDLE/RUNNING/PAUSED…), `x,y,z,offsetX/Y/Z,homed,nozzleTemperature,nozzleTargetTemperature,heatedBedTemperature,heatedBedTargetTemperature,workSpeed,laserPower,laserFocalLength,currentLine,totalLines,estimatedTime`. A 204 response means "waiting for confirmation". Three errors in a row disconnect. |
| upload and prepare print | POST `/api/v1/prepare_print`, multipart: `token`, `type`=`3DP`/`Laser`/`CNC`, `file`=<gcode> |
| start/pause/resume/stop | POST `/api/v1/start_print`, `/pause_print`, `/resume_print`, `/stop_print`, body `token=` |
| raw gcode | POST `/api/v1/execute_code`, body `token=&code=<gcode>` (sent line by line) |
| file to storage (<20 MB) | POST `/api/v1/upload`, multipart: `token`, `file` |
| chunked upload (≥20 MB) | POST `/api/v1/sliceUpload`, multipart: `index` (1-based), `count`, `md5` (whole file), `size`, `filename`, `file` (2 MiB chunk). Success text is `silce upload success` (typo is original) or `file upload complete`. |
| other | `/api/v1/setSystemTime` (`timestamp`), `/api/v1/print_file` (GET current file), `override_nozzle_temperature`, `override_bed_temperature`, `override_work_speed`, `override_z_offset`, `override_laser_power`, `filament_load`, `filament_unload` |
| camera | `:8080/api/request_capture_photo`, `/api/get_camera_image?index=`, `/feed.webm`, `/?action=stream` |

Response handling (`_getResult`): status 200, 201, 203, or 204 is OK. Any other status returns its text as the error message.

## 3. USB serial
- In `server/index.js` (SerialConnection, controller:Screen): serialport at **115200 baud**, 8N1 defaults.
- **Plain mode:** Marlin text, `\n` line delimiter.
- **Screen protocol (`isScreenProtocol`), Snapmaker SACP-like framing:**
  - Header (8 bytes): marker `0xAA 0x55` (43605); length (u16 BE); version (`0x00`); `lenVerify = (len>>8) ^ (len&0xFF)`; checksum (u16 BE).
  - Payload: eventID (u8) + optional u32 BE index + data.
  - eventIDs: 1 = gcode feeder, 3 = file sender (indexed).
  - Checksum: 16-bit one's-complement sum of big-endian 16-bit words (an odd trailing byte is added), then inverted.

## 4. Output format
- Plain-text **.gcode** from CuraEngine. There is no compression, no binary, and no MD5 in the file. (MD5 is used only for chunked uploads.)
- The server prepends this header:
```
;Header Start
;header_type: 3dp,0.3mm
;file_total_lines: N
;file_valid_lines: N
;estimated_time(s): S
;material_type: ...
;nozzle_temperature(°C): T
;build_plate_temperature(°C): T
;work_speed(mm/minute): F
;max_x(mm)/max_y/max_z/min_x/min_y/min_z: ...
;Header End
;G-code for 3dp engraving
;Generated by IVI 3licer
```
- **No `.supx` handling exists anywhere in the app.** `.supx` and `config.ini` (`version=`, `MD5=`) are firmware-update artifacts handled on the printer side. The `/api/file/uploadUpdateFile` route is only for the local server.

## 5. Constants, keys, and certificates
- No TLS certificates or crypto keys were found. The only secret-like value is the hardcoded default token above.
- `api_server: "http://3licer....` is the update/version server (`/api/version/latest`).

## Verified / open on the real printer
- **Verified (2026-10-31):** port 8080 is live (kore); a full 1–65535 TCP scan found no other open ports. Details: [network.md](network.md).
- **Verified:** the printer's USB-C port is a direct serial link to the STM32 Marlin (115200, plain line G-code, no `AA 55` framing). The `AA 55` screen protocol above is for the slicer↔UI-board path.
- **Open:** whether the default token is accepted without on-screen confirmation on every firmware build.
- Note: the bundled CuraEngine definition says 210×210×220 with center origin, but the printer is a **delta** (M665 L357.50 R160.31 H233.22); treat the volume as a round bed.
