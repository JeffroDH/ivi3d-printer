# GD32E230 soft-power controller

The rear bottom-right chip marked **E230F4** / lot `JJ2014` is a GigaDevice **GD32E230F4**: Cortex-M23, 16 KiB flash, 4 KiB SRAM **[P][D]**. Package looks LGA20; the exact orderable (F4V6 vs F4P6) is **[U]**. Photo and the SWD pad cluster: [mainboard.md](mainboard.md).

The firmware image is **not** in this repo. Two reads of the same chip were byte-identical. SHA-256 `540f4967976e390a5a1822347a148b332ee3da78329d03e1880c851ab17f0167`. Annotated listing, function list, and pseudocode: [research/gd32/README.md](research/gd32/README.md).

## What the firmware does

It is a button-driven power sequencer. Confidence is **high** for the behaviour below, because it is the whole program. Confidence is **medium or lower** for which board net each pin is, because no GD32 pin has been continuity-tested.

Clocks: internal 8 MHz RC, PLL ×18, 72 MHz, SysTick at 1 ms. The only interrupt is SysTick. RCU, flash wait states, GPIOA, GPIOB, and ADC channel 3 are the only peripherals. **No USART, I2C, SPI, timer, DMA, or watchdog is clocked.** The chip has no data link to the A33 or the STM32.

1. **Standby.** PA4, PB1, and PA7 are low. A press on PA1 (active low, 50 ms debounce) is required.
2. **Power on.** PA2, PA4, and PB1 go high. The chip waits for release.
3. **While on.** A short press toggles PA2. Holding about 3 seconds drives **PB1 low, then PA4 low 10 ms later**, and the chip returns to standby.
4. **Low analog input.** If the 10-sample average on PA3 is ≤ 1985/4095 (about 1.60 V if the reference is 3.3 V, which is not measured), PA7 latches high. After 3 seconds (6 seconds if PA6 is high) PB1 then PA4 drop, and the chip loops until reset.

The 3-second hold matches the front power button cutting the rails (PB1, then PA4). That pin assignment is **medium** confidence: the code does the sequencing, and the board has `BUTTON` and `LED_CTL` pads, but the nets are not traced.

| Signal | Likely role | TSSOP20 | LGA20 |
|---|---|---|---|
| PA1 | Button input | 7 | 4 |
| PA2 | LED or a toggled enable | 8 | 5 |
| PA3 | Analog sense | 9 | 6 |
| PA4 | Sequenced enable, off second | 10 | 7 |
| PB1 | Sequenced enable, off first | 14 | 11 |
| PA6 | Input; extends the low-voltage hold | 12 | 9 |
| PA7 | Output latched on low voltage | 13 | 10 |
| SWDIO / SWCLK / NRST | Debug | 19 / 20 / 4 | 16 / 17 / 1 |

Used flash is `0x08000000`–`0x0800113F` (4416 bytes). The rest of the 16 KiB is `0xFF`. There is no bootloader/application split and no strings. Initial SP `0x20000420`.

## SWD

The front lower 5-pin (top to bottom: DIO, 3V3, CLK, GND, RST) is continuous with the rear pads beside this chip **[O]**. Treat it as the GD32 header until chip-pin continuity is measured.

The same limits as the STM32 apply: no reset, no halt, no erase, no program, no option-byte writes, and never clear readout protection. Option bytes were not read. A live voltage check of PA4/PB1 is a separate authorization, not part of a debug session.

OpenOCD's `gd32e23x` target is the software that speaks this core. ST's STM32 utilities are not a GD32 programmer.
